# research-reflection skill

给研究 agent 用的回测复盘方法。它来自 2026-09-23 那一轮对真实回测的复盘,每一步都有真实翻车案例
(见 `references/cases.md`)。写给能力一般的模型:**按顺序走,每步只看指定字段,达到停止条件就停。**

输入:一份全窗口回测报告(`BacktestReport`,字段速查见 `references/fields.md`),以及代码算好的
零模型诊断(`diagnose_backtest` 的 findings,每条带数值)。统计方法的细节在 `references/stats.md`;
GLM 按本 skill 作答的基线与评估在 `references/examples.md`。

<!-- section:core -->
## 铁律(每一步都适用)

1. **数字只抄,不算,不编。** 结论里出现的每个数字,都必须能在报告或诊断 findings 里原样找到。
   本文件里的案例数字只是例子,不是你这次的数据,不许写进答案。算不出来就写「报告里没有这个数」。
2. **先核数,再解释。** 数字对不上时,任何归因都是空中楼阁。
3. **n < 30 只作观察。** 平仓笔数不到 30,不说「有效」「无效」「更好」,只说「这段历史上是这样」。
4. **观察和假设分开。** 观察 = 产物里的事实;「因为……」只能出现在假设里,并写明用什么验证。
5. **一次只改一个条件。** 提建议时同时改两处,下一轮就分不清是哪处起的作用。
6. **没做的检验就说没做。** 报告里没有随机入场基线、没有试验次数折算,就不能说「有优势」。

<!-- section:reconcile -->
## 第 1 步 核数:报告的总收益对得上吗

- 看:主资产 `metrics.total_return`;逐笔 `trades[].return_pct`;`warnings` 里的「期末仍有持仓」;
  `execution.sizing_mode`;`metrics.exposure` 与 `metrics.time_in_market`。诊断 finding `reconcile`、`sizing` 已算好。
- 怎么判:
  - 满仓口径(每笔 100% 权益)下,逐笔 (1+收益) 连乘 − 1 应≈ 总收益。差额 > 5%(相对净值)时必须找到来源:
    期末持仓按收盘价盯市(warnings 会写)、仓位不是满仓、篮子两腿各算各的。
  - 持仓期间的平均仓位 = exposure ÷ time_in_market。**低于 50% 时,收益和满仓持有不可比**,后面所有「跑输持有」都要先打折。
- 什么时候停:差额解释不了 → 停,答案只写「报告数字对不上,先查报告」。仓位口径失真 → 继续,但第 3 步必须用同敞口持有比较。
- 反例(9-23 真实):1% 风险仓位、单笔 ≤20% 资金,敞口只有 0.3%,却拿去和满仓持有比「−1.3% vs +1212.9%」,这个对比没有意义。

<!-- section:faithfulness -->
## 第 2 步 忠实度:回测的是用户说的那条策略吗

- 看:用户原问题 vs `strategy_ir`:`exit[]`(`chandelier_trail` 追踪、`structure_target`/`fixed_r_target` 止盈、
  `indicator_cross_exit` 信号离场)、`risk.stop`、`risk.sizing`、`order.entry`(限价挂在哪)、`order.take_profits`。
  诊断 finding `faithful_trail`、`faithful_target`、`faithful_stop`、`limit_wrong_side`、`param_mismatch` 已算好。
- 怎么判:
  - 用户没说、IR 里却有的离场(追踪 / 止盈 / 止损),而且 ≥ 30% 的平仓是它打出来的 → **这份报告测的不是用户的策略**。
  - 限价做多挂在信号收盘价**上方**(做空挂在下方)→ 限价等于追价市价单,「回踩」没有被表达出来。
  - 参数扫描变体:入场参数改了,离场参数没跟着改 → 变体之间的差别不纯。
  - 仓位是 risk_fraction(按风险下单)→ 回到第 1 步的仓位口径问题。
- 什么时候停:忠实度出问题时,结论先写这一条,建议「按原话重新编译再回测」,**不要再为这份报告做收益归因**。
- 反例:「死叉离场」被补了吊灯追踪和 2R 止盈,22 笔里 17 笔是追踪打出去的;「回踩 EMA20 限价买」被编成价格下穿 EMA20,
  限价全部挂在价格上方(161/161),下一根开盘就成交,成交率 100% 却没有一次真正的回踩。

<!-- section:benchmark -->
## 第 3 步 选对比较对象

- 看:`metrics.benchmark_return`(同窗口买入持有,同费率)、`metrics.exposure`、样本内外 `segments[].metrics`。
  诊断 finding `exposure` 里已给出「同敞口持有(粗算)= 持有收益 × 平均敞口」。
- 三个基准,都要想到:买入持有、**同敞口持有**、资产池等权持有(报告里有 BTC+ETH 篮子时用篮子的持有)。
- 怎么判:
  - 择时策略(大部分时间空仓)**不能只拿总收益比持有**:单边上涨里空仓天然落后。择时有没有贡献,看它是否跑赢同敞口持有。
  - 同时看样本外段:样本外策略 vs 样本外持有,比全窗口更能说明问题。
  - 做空或双向策略:持有基准是做多,超额里含方向差,不是同方向对照。
- 什么时候停:三个基准都跑输 → 结论就是「这段历史上没有择时价值」,第 4 步只找最大的一个来源。

<!-- section:attribution -->
## 第 4 步 拆来源:收益差从哪来

按下面顺序逐项看诊断 findings,**只挑贡献最大的一到两项写进结论**,不要平铺:

1. 在场时间 / 敞口(`exposure`):在场 < 50% 且持有 > 50% → 空仓是落后的首要来源。
2. 按退出类型的盈亏(`exit_mix`、`stop_tight`、`worst_exit`):止损打出 > 40% 且合计为负 → 止损过紧或入场离结构太远。
3. 收益集中度(`concentration`):前 20% 交易的盈利 > 全部净利 → 其余交易整体在亏,换几笔结果就变。
4. 样本内外衰减(`decay`):样本内为正、样本外转负 → 规则可能只适配前段行情。
5. 成本拖累(`fees`):手续费 + 滑点 > 毛盈亏的 30% → 交易太频繁或周期太低。
6. 逐资产(`assets`):BTC 和 ETH 方向相反 → 结论不能推广到「加密资产」。
7. 被拦的计划(`blocked`,只有订单周期报告有):`min_rr` 盈亏比不足、`stop_side` 止损在错误一侧、`gap_invalidated` 跳空失效。
   被拦 > 50% → 信号出现的位置和止损/目标的几何不匹配,而不是信号本身差。
8. 止损被放宽(`stop_widened`):止损备注里有 `cost_floor` 的比例 > 50% → 策略自己的止损在这个周期不起作用,实际是 2.4% 的成本下限在止损。
9. 成交率(`fill`):限价 no_fill 很多 → 收益只来自少数成交,样本比看上去更小。

什么时候停:找到一个能解释大部分差距的来源就够了;来源之间互相打架时,写成两条并列假设。

<!-- section:signal_noise -->
## 第 5 步 是信号还是噪声

依次过这几道门,**任何一道没过就停在那一档**:

1. 笔数:平仓 < 30 → 结论档位最高只能是「观察」。
2. 随机入场基线:同样的止损/离场、随机时间入场、同样笔数。报告里没有这个基线 → 写「没有随机入场基线,不能说入场有优势」。
3. 试验次数:这是同一策略的第几个变体?(finding `variants`)从 N 个变体里挑最好的,优势要按 N 折算(Deflated Sharpe ≥ 0.95 才算扛住)。
   只试了 3–4 个变体也要说,「4 个里挑出来的」和「预注册的一个」不是一回事。
4. 置换检验必须保留时间结构(循环平移、块置换);逐根打乱会让任何挖掘结果都「显著」。
5. 多重检验:同时看了很多规则 / 资产 / 周期,要做 BH 校正;只报最好的那个等于选择偏差。
6. 配对比较:两个方案在同一批交易上比,看差值的置信区间;区间跨 0 → 「分不出」,不是「更好」。
7. 行情段:样本内外是不是完全不同的行情(单边涨 vs 单边跌)?只做多的规则在单边跌里没有正期望是正常的。

结论只用四档:**噪声 / 分不出 / 有迹象(需复验) / 通过复验**。本工作台单次回测最多到「有迹象」。

<!-- section:next_step -->
## 第 6 步 提出下一步

- 只针对第 4 步找到的**最大来源**提一个改动,一次只改一个条件,在**同一窗口、同一资产、同一成本**下对照。
- 常用对应:空仓太多 → 放宽方向门或加资产;止损过紧 → 换结构位止损或放宽 ATR 倍数;止损被成本下限放宽 → 换更高周期;
  样本外衰减 → 减少条件;利润集中 → 分档止盈或保本;成本拖累 → 更高周期或限价入场;某类离场亏钱 → 只换这一段离场。
- 忠实度有问题 → 下一步永远是「按用户原话重新编译,再回测」,排在所有改进之前。
- 参数要改就先想好要试几个值,试完按试验次数折算;留出段只用一次,不许回头挑。

<!-- section:writing -->
## 第 7 步 报告写法

固定三段,顺序不变:

- **观察**:产物里能直接看到的事实,每句都带出处(哪条 finding / 哪个指标)。不写「因为」。
- **假设**:一到两条可能的原因,用「可能」「待验证」措辞;每条对应第 4 步的一个来源。
- **验证**:每条假设配一个具体的下一次回测(改哪一个条件、和谁对照、看哪个指标)。

禁止:编数字、算新数字(包括百分比换算)、把「样本不足」写成「无效」、把「跑输持有」直接写成「策略没用」、
在观察里下因果结论、说「显著」却没有做检验。

<!-- section:loop_answer -->
## 在研究 loop 里作答(compose_answer)

- 只输出 JSON `{"blocks":[...]}`。复盘内容写成三个 `text` 块,分别以「观察:」「假设:」「验证:」开头。
- 诊断列表系统已经原样展示给用户,**不要逐条复述**。观察最多 4 句,只写最重要的 1–3 条 finding(按第 2 → 1 → 4 步的顺序挑),
  假设最多 2 条,验证每条假设配一个下一次回测。不要写 finding 的英文 key(如 exposure、decay),用中文说是哪一条。
- 数字只能从 `findings` 与 `observations` 里原样照抄;任何对不上的句子会被系统删掉。不确定就不写数字,
  用文字指明出处,例如「见在场时间那条诊断」。
- findings 里 severity=high 的项必须在观察里出现;忠实度类 finding(key 以 faithful_ 开头、limit_wrong_side、param_mismatch)
  存在时,观察第一句写它。
- 不描述回测「是否已执行 / 待执行 / 需确认」,执行状态由系统写。
