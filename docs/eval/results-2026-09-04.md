## 为什么还是零 PROPOSE(读了 36 个非 halted scan 判断的 reasons)

模型给的拒绝理由高度集中,且**每条都是 playbook 里写死的门槛**:
1. `ATR% < 0.4%`(15m ATR 在 0.07%–0.25%)——8 月这段 15m 数据几乎全在门槛之下;这条 NO_TRADE 条件把 15m 周期整个封死了。
2. 量比 < 1.0(0.15–0.9 居多)——"回踩确认要量比 ≥ 1.0"在回踩时天然不成立(回踩就是缩量)。
3. 1h 与 4h 方向相反 → NO_TRADE。
4. "价格距 20 根高点 0.20%–0.34%,**未突破**"→ 只 WATCH;v3 加的"突破刚发生就挂限价"从没触发,因为 case 抽样是均匀随机的 as_of,恰好落在突破那根收盘上的概率很低。

所以这不是模型胆小,是 **playbook 阈值 + case 抽样** 共同决定了 PROPOSE 在这个集合里几乎不可达。两条路:
- 校准 playbook:ATR% 门槛按周期分档(15m 用 0.15%),回踩量比条件去掉或改成"突破那根量比 ≥ 1.5";
- 让 case 生成器**按触发器抽样**(用 `demo.detectTriggers` 在历史上找 breakout/retest/ema_cross 命中的时刻做 as_of,而不是均匀随机),这样 scan case 才是"本该有机会"的样本,PROPOSE 率、闸拒率、outcome 才有分母。这也正是 `trigger_precision` 指标需要的数据。

## 复查侧的 HOLD↔EXIT 翻转(26 个不同里的 17 个)

同一 case、同一证据,v1 说 HOLD、v3 说 EXIT(或反过来)。两版 prompt 对复查的规则没改,差异来自模型本身的不稳定 + 复查块里没有"距止损多远/浮盈多少 R"这种结构化字段,模型自己算差值(这也是剩下 3 个幻觉数字的来源)。修法与打分报告的建议 2 一致:把线程块的入场/止损/止盈/浮盈登记成 E 证据(代码算好 R 倍数),模型只引用不算。

## 去噪后的结论(`runs/pi-v3-s5`,cases/v1 108 例 × 5 样本,GLM-5.3,≈¥2.4)

对比文件:`runs/compare-v3-single-vs-s5.md`(v3 单次 vs v3 五次众数)、`runs/compare-v1-vs-v3-s5.md`(v1 单次 vs v3 五次众数);eval-a 的 runs/ 不入库,三份 markdown 已抄到 `docs/eval/runs/`。口径见 `docs/eval/denoise-plan-2026-09-04.md`(与 Codex 合并的 v2)。

**噪声底 29.6%,与上午 33% 的单次重跑一致;self_consistency 70.4%,没过 0.8 的建议线。** 108 个 case 里 78 个稳定(众数 ≥ 4/5),30 个不稳定;一致度分布 1.00×44 / 0.80×34 / 0.60×29 / 0.40×1。scan 的一致性 74.2%,review 67.3%——复查比扫描更摇摆。

| 项 | 值 | 怎么读 |
|---|---|---|
| noise_floor | 29.6% | 同一输入再问一次,约三成动作会变 |
| 稳定 / 不稳定 case | 78 / 30 | 动作类指标只在 78 个上算 |
| 不稳定的翻转对 | NO_TRADE↔WATCH 12,EXIT↔HOLD 10,其余 8(HOLD↔REDUCE、EXIT↔INVALIDATE、三选一) | 噪声集中在两条"边界":扫描时"值不值得盯"、持仓时"该不该走" |
| 不稳定按变体 | base 6/12,stale 4/12,rev2 4/12,mirror-rev1 4/12,mirror-rev2 4/12,rev1 3/12,mirror 2/12,rev3 3/12;**halted 0/12** | 有硬规则的地方(halted 只能 NO_TRADE)就稳,靠模型自由裁量的地方就抖 |
| 硬不变量按样本(n=540) | hallucinated 10(众数样本 1)、unauthorized 2、illegal_edge 2、leakage 0、stale 0、path_replay 100% | 硬指标被多采样放大了但没变质:仍是"模型自算差值"和 halted 上偶发 WATCH 两类 |

**v1 → v3 的差异在去噪后剩下什么。** 78 个两边都稳定的 case 里,v1 与 v3 众数动作一致 87.2%(68/78),差 10 个;v3 单次与 v3 众数一致 92.3%(72/78),差 6 个。也就是说,v3 单次 run 自己和自己的"真值"就差 6 个,v1 与 v3 的 10 个差异里估计有一半以上仍是 v1 那一侧的单次噪声(v1 没跑多采样,噪声底按 0 计只是没测)。上午报告写的"26 处 v1 vs v3 差异、17 处 HOLD↔EXIT 翻转"应改读为:**能落实到 prompt 改动的真差异不超过 10 处,且方向不一致(v1 HOLD → v3 EXIT 有 4 例,反向 1 例)**,不足以说 v3 "更保守"或"更激进"。硬不变量那一半的结论不受影响:evidence_valid 97.2% → 100%、幻觉 13 → 10/540 样本(众数样本 1)是真的。

**两个硬不变量 FAIL 都在 halted 上。** ethusdt-20260808T2145-halted 与 20260819T2300-halted 各有一个样本在 scan:halted 节点输出 WATCH(允许集只有 NO_TRADE),这是 v1 时就有的同一处毛病,5 样本里各只中 1 次(众数是 NO_TRADE),所以按 case 是 0、按样本是 2。运行时这一步会被闸截住并修一次,线上不会漏,但说明 playbook 对"紧急停止时只准 NO_TRADE"的措辞还不够硬。

**对 harness 的含义。**
1. 任何单次 run 的动作类结论从此都要附噪声底;晋升门 self_consistency ≥ 0.8 暂不硬卡(现在 0.70,卡了就全 HOLD),先当报告项。
2. 降噪不能靠多问,要靠把摇摆边界写成规则:WATCH 与 NO_TRADE 的分界(什么条件下才值得开线程盯)、HOLD 与 EXIT 的分界(浮亏几 R、跌破哪条线)——都应进 playbook 或进结构化证据(R 倍数由代码算好给模型),这与"复查块结构化"是同一件事。
3. 成本:5 样本 ¥2.36、19 分钟(并发 4);cost_latency 行的 token/延迟是每 episode 五个样本之和,别按单次读。
4. 零 PROPOSE 与多采样无关,仍卡在 gen 抽样方式,见「下一步」。

**没做**:outcome/calibration 逐样本均值、case-bootstrap 置信区间、side_symmetry / thesis_continuity 改"稳定对"口径、zai-api t=0 旁路诊断(只做了大脑,没跑)。

prompt `demo-playbook-v5`(v4 的边界规则 7/8 + 代码算的扫描清单/持仓度量 + 策略块与规则 9)。报告抄在 `docs/eval/runs/pi-v5-unstable-report.md`。

**边界往哪边收了。** 逐 case 对比 v3 众数 → v5 众数:扫描 12 例里 6 例变了,全是 WATCH → NO_TRADE(v5 只剩 2 例 WATCH,都是 ETH 08-22 18:15 那组);复查 18 例里 7 例变了,主要是 EXIT/REDUCE → HOLD(5 例),另有 1 例收敛到 REDUCE、1 例收敛到 EXIT。也就是说规则 7、8 确实按设计把模糊地带判给了"不动"。代价要盯:这 12 个扫描 case 的 missed_move 均值 8.48 ATR、91.7% 超过 2 ATR——不交易之后市场确有大波动。这不等于错失盈利(指标不给方向),但说明 v5 的 WATCH 门(watch_eligible=是 才能 WATCH)偏严,尤其 ATR% 门槛在这批 8 月 case 上按周期分档后仍多数"不足"。**PROPOSE 仍为 0**,与采样无关,仍是 gen 均匀抽 as_of 的问题。

## v5 全量结果(`runs/pi-v5-s5`,2026-09-05,108 例 × 5 样本,541 次调用(151 次命中定向 run 缓存),¥3.25,21 min)

对比 `runs/compare-v3s5-vs-v5s5.md`(抄在 `docs/eval/runs/`)。

**噪声:** noise_floor 29.6% → **1.5%**,108/108 稳定(104 个 5/5,4 个 4/5),残留翻转 EXIT↔HOLD 3 例、NO_TRADE↔WATCH 1 例。采样噪声问题就此关闭——边界规则化 + 代码算数字有效,不需要多问取众数。

**硬不变量:** 幻觉数字 10 → **0**(1R 风险值由代码给出后彻底消失);证据引用 100%;越权/越图各 1/540 样本,仍是老地方 `ethusdt-20260822T1815-halted` 上 5 次里 1 次输出 WATCH(众数 NO_TRADE)。晋升结论 HOLD 只因这一个样本;要修就把 halted 节点的允许集直接写进 system 规则(现在靠 playbook 措辞)。

**边界收向了"不动",且幅度不小。** 78 个 v3 原本稳定的 case 里 29 个众数动作变了(一致率 62.8%),全部是单向的:EXIT → HOLD 10 例(长 7、短 3),WATCH → NO_TRADE 14 例,INVALIDATE 相关 5 例(HOLD→INVALIDATE 4、INVALIDATE→EXIT 2,方向不一)。全量 action_mix:NO_TRADE 45 / HOLD 42 / INVALIDATE 10 / EXIT 4 / REDUCE 4 / WATCH 3,对比 v3 的 EXIT 11、WATCH 11。变化集中在 stale(5)、mirror 系(12)——即证据偏旧或方向镜像的 case,规则 7/8 在这些地方判"条件不成立就不动"。

**这是好是坏,现在判不出来。** 零 PROPOSE 之下没有 outcome_R;复查 case 的 HOLD/EXIT 也没有反事实结算。有两组数字提示要警惕:missed_move 6.87 ATR、83% 超过 2 ATR(与 v3 持平,不是 v5 变差,但 WATCH 从 11 降到 3 意味着更多机会连"盯"都不盯);EXIT 只剩 4 例,如果 v3 那 10 个 EXIT 里有一部分是对的,v5 会多扛亏损。要回答这个问题需要两个新指标:①复查 case 的**反事实 R**——用 hidden K 线按线程止损/止盈结算"HOLD 到底"与"此刻 EXIT"各值多少 R,对比众数动作;②gen 按触发点抽 as_of 让 PROPOSE 有分母。这两个比再调规则措辞更重要。**两个都在 2026-09-05 做完了**:①见下节「复查反事实 R:v3 vs v5」——答案是 v5 那批 EXIT→HOLD 翻转在这批数据上净亏 6.39R;②见 `cases/v2`,真模型 run 待放行。

**结论:** v5 解决了"同一输入答案随机"这件事,代价是把模糊地带一律判为不动;下一轮不要再动规则,先补反事实 R 与触发点抽样,用数字决定 watch_eligible 和 EXIT 条件该放宽多少。

## 复查反事实 R:v3 vs v5(2026-09-05,回答「v5 的 EXIT→HOLD 翻转是帮了还是害了」)

指标 `review_counterfactual` 已实现(`packages/eval-a/src/counterfactual.ts`),两次 run 的报告已用它重算:`runs/pi-v3-s5/report.md`、`runs/pi-v5-s5/report.md`、对比 `runs/compare-v3s5-vs-v5s5.md`(都抄在 `docs/eval/runs/`)。

**口径。** 每个复查 case 用 hidden K 线结算两次:`hold_r` = 什么都不做,从线程成交价持到止损/止盈,两个都没碰到就按 horizon 末根收盘 mark-to-market;`exit_now_r` = 按 as_of 收盘价平掉。挂单则是 `keep_r`(留着,horizon 内没成交 = 0)对 `invalidate_r` = 0。R 的分母始终是开仓时的 |成交价 − 止损|,和 outcome_R 用的是同一份 `openTrade/stepTrade/tradeR`(现在住在 gateway 的 `outcome.ts`)。chosen = 该 case 的众数判断(HOLD→hold,REDUCE→半 hold 半 exit,EXIT/INVALIDATE→exit_now),best = argmax,regret = best − chosen。**单路径**:不再入场、不分批、无手续费与滑点。所以下面的数字是方向性证据(这批判断整体偏早还是偏晚、偏多少 R),**不是策略盈亏**。

**答案:v5 的 EXIT→HOLD 翻转在这批数据上是亏的,不是赚的。**

取两次 run 都采样稳定的 **42 个复查 case**(同一批 case、同一批 hidden K 线,唯一变量是判断):

| | v3(pi-v3-s5) | v5(pi-v5-s5) |
|---|---|---|
| 平均 regret R | 0.27 | **0.42** |
| 选中最优的比例 | 66.7% | **45.2%** |
| 42 个 case 的 chosen R 之和 | **+2.73** | **−3.65** |
| 判 HOLD:事后 HOLD 更好 / EXIT 更好 | 11 / 11 | 8 / 20 |
| 判 EXIT+INVALIDATE:事后 EXIT 更好 / HOLD 更好 | 14 / 4 | 4 / 7 |
| 判 EXIT 的 case 上「改成 HOLD」平均 | −0.47R(EXIT 走对了) | −0.18R |
| 判 HOLD 的 case 上「改成此刻离场」平均 | +0.23R | +0.41R |
| (对照)这 42 个 case 的 hold_r 均值 / exit_now_r 均值 | −0.13 / +0.19 | 同左(case 属性,与判断无关) |

17 个动作翻转,合计 **−6.39R**(平均每个翻转 −0.38R)。拆开看:

- **EXIT → HOLD 11 例,几乎全是亏的**:`btcusdt-20260826T2245` 那条链(3+1 例)和 `ethusdt-20260819T2300` 那条链(4 例)HOLD 之后直接走到止损 −1R,而 v3 的 EXIT 分别只亏 0.03–0.55R,单例代价 −0.45 到 −0.97R;`ethusdt-20260823T0615-mirror-rev1` −0.40R。只有 `ethusdt-20260822T0945-mirror-rev3` +0.09R 是赚的。
- **HOLD → INVALIDATE 4 例(挂单),0R**:`btcusdt-20260801T0300` 那条链的限价单在 horizon 内根本没成交,留着和撤掉等价 —— v5 在这里"更果断"没有代价,也没有收益。
- **INVALIDATE → EXIT 2 例、EXIT → REDUCE 1 例,±0R**:同一个持仓的同一个出场价,只是措辞不同。

把范围放宽到全部 60 个复查 case(v3 那边包含 18 个采样不稳定的众数,读数要打折)结论同向:chosen R 之和 15.37 → 11.12,平均 regret 0.305 → 0.376,选中最优 66.7% → 53.3%,24 个翻转合计 −4.25R。

**怎么读。**
1. v5 的规则 7/8 把"模糊地带一律不动"写死了,而这批 8 月数据里,持仓复查的模糊地带**更多是该走的**:v5 判 HOLD 的 42 个 case 里 20 个事后 EXIT 更好(v3 是 11/22)。代价集中在少数几条链上——两条链、8 个 case 就吃掉了大半的 −6.39R,因为链上相邻步骤共享同一段未来,**样本独立性很弱**,不要把 −6.39R 当作 42 个独立样本的统计量。

## v6 设计集单样本 + stale 复验(`runs/pi-v6-design-s1`,2026-09-05 深夜,cases/v3-design 124 例 × 1,¥0.75,≈4 分钟;`runs/pi-v6-holdout-stale-recheck*`)

设计集 = BTC/ETH 2026-08-07 至 08-30,是写规则时看过的资产与时段。报告抄在 `docs/eval/runs/pi-v6-design-s1-report.md`,并排对照 `docs/eval/runs/compare-v6-design-vs-holdout.md`。

**硬指标**:幻觉 0、越权 0、越图 0、未来泄漏 0、路径重放 100%。FAIL 的两项都是 stale 变体:2/14 个 stale case 模型仍 PROPOSE(规则 4「标了 STALE 的证据不能作为 PROPOSE 的依据」被 GLM 忽略),但这次全被新加的「行情快照过期即拒」闸拦下(闸理由「行情快照已过期 600 秒」);保留集复跑 DOGE 的 stale case 同样被拦。所以 eval 的 `stale_trade` 现在量的是「模型有没有听话」,不是「会不会真开单」——真开单这一层已经堵住。建议:把 stale 从 prompt 规则提到图层(行情证据 STALE 时 allowed_actions 去掉 PROPOSE,像 halted 只允许 NO_TRADE 那样),模型输出 PROPOSE 直接算非法边而不是靠它自觉。

**开单与机械基线**:PROPOSE 6 例(3 个基础时间点 × 正/镜像),agent +0.16R、同 case 机械 −1.00R,配对 edge +1.16R;跳过的 50 例机械 +0.00R 与全样本 −0.11R 相比,选择性 −0.11R(跳过的那批并不比全体差)。与保留集(5 例 +0.01R vs 机械 −1R)方向一致,样本仍小。

**复查方向(关键)**:设计集选中事后最优 **54%**(保留集 65%),平均 regret 0.43R;判 EXIT 的 51 例若改 HOLD 平均 **+0.17R**(保留集是 −0.14R),判 HOLD 的 11 例若改此刻离场 +0.54R。也就是:v6 的「EXIT 为主动作」在 9 月普跌的保留集上是对的,在 8 月的设计集上是错的方向——**EXIT/HOLD 的判别力接近硬币,规则 8 的收益是行情给的不是模型给的**。下一步不该再改规则松紧,而是给复查加结构化的"持有价值"证据(例如 hidden 前的趋势/动量分位),再用两集合并看 regret 是否下降。

**regime_agreement 6.7%(1/15)的原因查清了:是口径 bug,不是模型逆势。** eval-a 的 `inputs.ts caseToInputs()` 没有把 case 里的 1d K 线算成 `daily_regime` 传给 `buildContext`,124 个 episode 的 context 里 0 条「日线状态」证据——模型根本没看到日线状态,指标却拿 `dailyRegime()` 去对它的方向。线上 runtime 是传的。修法:`caseToInputs` 里 `daily && daily.length >= 30 ? demo.dailyRegime(daily, as_of) : null` 塞进 inputs(与 counterfactual.ts 的 regimeRow 同一口径),然后设计/保留两集各重跑一次(≈¥1.6)才知道真实的顺逆势比例。修完 context 会变(多一条 E),按规矩升 PROMPT_VERSION 不必(prompt 文本不变,证据条数变),但缓存键会因 context 变而自然失效。

**其他**:trigger_precision 66.7%(24/36;retest 2/6、ema_cross 0/2 偏低);missed_move 92% 的 NO_TRADE/WATCH 后有 >2 ATR 位移(WATCH 门仍偏严,与 v5 结论一致);成本 ¥0.75 / 124 次 = ¥0.006/次。

**下一步顺序**:① 修 eval 的 daily_regime 口径 → 两集重跑;② stale 提到图层;③ 复查加"持有价值"结构化证据后再比 regret;④ 触发点抽样已在(v3 集),retest/ema_cross 精度低要看是否触发器定义的问题。


## v6r:补上日线状态/交易时段证据后的两集重跑(`runs/pi-v6r-design-s1` ¥0.77、`runs/pi-v6r-holdout-s1` ¥0.85,2026-09-06 凌晨)

改动只有一处:eval-a `inputs.ts` 把 `daily_regime` 与 `session` 传给 `buildContext`(与线上 runtime 同口径),每个 context 多两条 E(日线状态 / 交易时段)。prompt 与图不变(graph v2 的 scan:stale 节点是重跑之后才提交的,这两跑没用到)。报告与并排对照抄在 `docs/eval/runs/pi-v6r-*-report.md`、`compare-v6-vs-v6r-*.md`。

**动作稳定**:与 v6 单样本比,设计集一致率 94.3%(7/124 变)、保留集 95.8%(6/142 变),变化全落在 EXIT↔HOLD、PROPOSE↔WATCH/NO_TRADE 这两条已知噪声边界,没有系统性偏移;硬指标不变(幻觉/越权/越图 0)。多两条证据没有让模型更谨慎或更激进。

**PROPOSE 结算翻了(单样本噪声,别当结论)**:设计集仍是同 6 个 case,但 ETH 0820 mirror 这次 stop 而非 tp(止损价从 2321 放到 2300.5),期望 +0.16R → −0.16R;保留集 PROPOSE 5 → 3,DOGE mirror 改成 NO_TRADE,剩下 3 单全止损,和机械基线打平(edge 0)。两集合计 9 单里 agent 只赢了 1 单;上一轮 11 单赢 3 单。**在 30% 噪声底下,单样本 PROPOSE 的 R 是掷硬币,只有 5 样本众数 + 更多基础时间点才能说话**;目前唯一稳的结论仍是"机械基线在这些 case 上全亏,agent 至少没更差"。

**regime_agreement 口径修正(两处)**:①之前 0 条日线证据是 harness bug,已修;②修完发现 0/14 全是 EXIT 判断——GLM 在每次复查都把线程方向回填进 `direction`,而 counterfactual.ts 拿 `direction` 当模型立场,等于在给 case 生成器打分(v3 集刻意开逆日线的线程)。现在 EXIT/INVALIDATE 一律不计分,HOLD 按线程方向的也只记行不计分。**修正后:设计集可计分 2 例(日线全是震荡/高波动,没方向)、保留集 3/3 顺势(BNB 0904 的 base/mirror/stale 三个变体)。样本太少,但"模型三分之二逆势"这个说法撤回——那是口径造出来的。**

**复查方向**:保留集选中最优 66.7%(v6 65.4%),设计集 58.8%(v6 54.4%),EXIT→HOLD 在设计集 +0.11R(v6 +0.17R)——结论不变:EXIT/HOLD 判别力弱,靠行情。

**stale**:设计 2 例、保留 1 例模型仍 PROPOSE,全被闸拦;graph v2 已把 scan:stale 的允许集改为 NO_TRADE/WATCH,下次跑 stale_trade 应从"闸拦"变成"非法边"计数(illegal_edge_attempts),这个硬指标的语义要跟着改:stale 变体输出 PROPOSE 记 illegal_edge 而非 stale_trade。

**下一步**:① 两集各跑 5 样本(≈¥8)拿 PROPOSE 众数与稳定 R,这是判断 agent 选单价值的唯一可信方式;② eval 的 stale_trade 指标改读图节点;③ 复查加"持有价值"证据(趋势/动量分位),再比 regret。
