# 让 agent「活」起来:10 分钟可跑的交互式演示(2026-09-03 晚)

问题:现在的 demo 是「每 15 分钟安静地判断一次」,看的人感觉不到 agent 在干活,也不知道它在想什么。目标:开一个页面,10 分钟内不用等,能看到 agent 读市场、判断、下单、跟单、复查、被问、被改设置的完整一轮,而且每一步都有人话反馈。

## 1. 三个机制(后端已落地)

1. **旁白(narrate)**:agent 每做完一件事就在对话里主动说一句人话,进 `chat.message` SSE,Agent 页和交易页的 Agent tab 都能看到。触发点:一次扫描/复查结束(「刚看了 BTCUSDT(1m 收盘):先观察 —— 多周期矛盾…下次看:…」)、入场成交/限价挂出、止损止盈触发/平仓(带盈亏)、信息员更新(regime/偏向/候选/风险)。工作流里 `narrate` 可关。
2. **判断进度(episode.progress)**:每次判断按步推送 `fetching → context → thinking → validating → gating → executing → done`,同时写进 `queue.state.running.step`。顶栏的「判断中 BTCUSDT」可以显示到「正在思考」「正在过闸」,判断卡片的骨架态也能逐步点亮。
3. **演示节奏预设(`TG_DEMO_SHOWCASE=1`)**:周期 1m(K 线每分钟收盘 → 每分钟至少一次扫描/复查)、信息员 3 分钟一次、观察列表 6 个币、旁白开。工作流允许的周期加了 1m/3m,信息员最短 2 分钟。10 分钟时间线大致是:0:00 信息员 → 0:30 六个币首轮扫描(每个 ~15 s)→ 1:30 起每分钟收盘触发 → 中间出现 PROPOSE 就开仓、挂保护、下一分钟复查 → 你随时在对话里问「为什么不做多 BTC」或点「立刻扫描」→ 3:00/6:00/9:00 信息员再更新。

## 2. 前端要补的(小改)
- 顶栏队列 chip 显示 `step`(拉行情 / 登记证据 / 思考中 / 校验 / 过闸 / 执行中)。
- 判断记录页正在跑的卡片按 `episode.progress` 逐步点亮六个步骤。
- 判断卡片加「问 agent 为什么」按钮:把 `episode_id` 带进对话,预填「解释一下 <symbol> 这次为什么 <action>」;agent 用 `get_thread`/记录回答。
- 旁白消息用淡一点的样式与用户对话区分(现在以「旁白 ·」前缀区分)。
- Agent 页加一个「演示节奏」开关(= 工作流 timeframe 1m + info 3 min),不用改环境变量。

## 3. 怎么跑
```
TG_DEMO_SHOWCASE=1 ./start-demo.sh
```
纸面模式下每分钟一次 GLM 判断约 ¥0.006,10 分钟六个币最多几毛钱。
