## 哪里判断错了
1. **把「加了一个分支」当成「修了一个失效模式」。** 例如入场单状态不明:我加了 ORDER_UNKNOWN 保持待入场,但保留了「连续 4 次查不到就 canceled」,Codex 指出这仍是把 null 当否定事实;止损单 unknown 我只查一次 CID 就补偿。正确的口径是 Codex 一直说的:**未知只能靠多源(订单 / 全部订单 / 成交 / 仓位)持续闭环,不能靠次数。**
2. **修一处不看它的邻居。** 发单前重闸排除了线程自己,但日内计数没排除,于是上限 N 实际是 N-1;线程找回订单了,意图却还停在 unknown,全局闸永远拦。这类「同一事实存两份、只改一份」的 bug,根因是 intent 和 thread 各记一份状态,和 8794 那句「不引入第二真相源」是一回事。
3. **写了 `sent` 标记但从没在发送时置位。** CLI 超时被判成确定失败,是最危险的一条:交易所可能已收单,而线程被取消。这个属于自己能测出来却没测的,我给后端只做了公共路径的探针。
4. **§10 的措辞过满。** 「已修」应该写「已加分支,未闭环」。以后每条修复都要带一个能失败的测试,否则只算 PARTIAL。

## 现在做的(本次收口,见 git log)
- 日内开仓计数排除当前线程;`entry_lookup_misses` 变成线程契约字段并随 version 走;找回订单同时把意图从 unknown 解冻;意图与线程终态同步。
- 紧急停止期间不挂任何保护单;`HALT_INCOMPLETE` 的币每次巡检重试撤单/平仓;平仓只有 `closed=true` 或新鲜账户证明已平才算成功,否则 `CLOSE_FAILED` 留巡检。
- 部分成交撤余量失败 → `ENTRY_REMAINDER` 不被保护流程清掉,每次巡检重试撤余量,余量未撤前不算「保护完整」。
- binance-cli:写类命令超时一律 ambiguous;"已不存在"只认 -2011/-2013;Rust 后端同样只认这两个码。
- 减仓 unknown/failed 不改本地数量;暂停期间不调模型(手动/对话扫描也不排队);sizing 实际风险超预算 5% 即拒(不再放宽到 1.5 倍)。
- 对话:`propose_thread` 一律进待确认(不管 auto_approve);`close_thread` 只生成待确认的平仓意图,审批走同一个入口。
- CID:线程前缀改用 sha1(thread.id) 的 12 位,腿序号用线程上的 `leg_seq` 单调递增,不再用时间尾。
- 交易规则缓存 10 分钟过期,发单前拒绝非 TRADING 的币。
- Rust:测试 base URL 只接受 `http://127.0.0.1` 后紧跟 `:`/`/`/结尾且不含 `@`;`close_position` 识别双向持仓,按 LONG/SHORT 各自带 positionSide 平仓且不带 reduceOnly。

## 对 eval 的含义
判断链(context → 大脑 → 校验 → 闸)与执行链是两回事;这次两份 review 都在执行链。eval 规格只覆盖判断链,执行链要的是**故障注入矩阵**(late success / null / partial / cancel race / HALT race / 双侧仓),记为 eval 的下一期。
