# Jev 实盘判断:影子判断 + 判断账本 + 判断流(2026-09-25)

契约增补,挂在 §9.53 C(IR judge 块)之后。`docs/demo/v3-ui-contract.md` 由另一个会话在改,本节合并时整段搬过去即可。

## 0. 起因(核实过的现状)

- Jev 只在 IR 带 `judge` 块时才通过 `strategy-run.ts` 的 `deps.judge`(runtime.judgeRuntime)参与,且是挡单语义。
- 18811 现有 3 个运行(`run_3ffeab26…` running,另两个 stopped)都没有 judge 块;`research_judge_decisions` 1405 条全部是 `matrix:`(回测,1398)和 `asp:`(7)前缀,实盘一条没有。
- 前端没有任何地方能看到单次 Jev 判断。

## 1. 影子判断(shadow)

**什么时候做**:策略运行 `scanInner` 里,候选 `claim` 落库、`candidate` 事件写完之后,挡单判断 / 过滤 / 下单之前发起。只对 IR **不带** judge 块的候选做;带 judge 块的维持原挡单语义(见 §2)。

**问什么**:默认模板 `take + quality`(`templateJudge(profile.ref, {templates:['take','quality']})`),state 用 `buildJudgeState`,与回测同一实现。盘口/清算特征照常读录制源(`micro-source.ts` 的 `recorderMicrostructure()`):六项(失衡、上下挂单墙、价差、多空清算)**全部可用**才把它们带进问题,否则退回不带盘口的模板,并在账本 `state.micro` 里标明 `book / liquidations / used / note`。

**不影响下单**:影子结果只写账本和推 SSE,不写 `strategy_run_events`,不改运行统计,不改 follow 语义。`agent` 模式的过滤器、`signal_only`、`confirm` 全部照旧。

**调用方式:fire-and-forget(不 await),不用短超时。** 理由:

1. 下单链路零附加延迟。短超时哪怕 1–2 秒也会推迟 `next_open_market` 入场;而且 `scanInner` 跑在运行器的 `serial` 队列里,和别的运行、开平仓、移损串行,await 一个模型调用等于把整条队列拖住。
2. 短超时并不能真正"取消"一次已发出的付费请求,只是不等它;fire-and-forget 同样不等,却不需要在下单路径上放一个 race。
3. 失败隔离更彻底:影子调用被包在 `runShadowJudge`(内部 try/catch,永不抛错)里,外层再 `Promise.resolve().then(...).catch(() => {})`,再外层 `try {} catch {}`;异常没有任何路径进 `scanInner` 的 catch,也不会把运行打成 `error`。
4. 风险面可控:同一运行器同时在途的影子判断上限 `JEV_SHADOW_MAX_INFLIGHT = 4`(Jev 客户端并发上限是 8,影子最多占一半,挡单判断永远有空位);超出直接跳过并记一条 `shadow_busy`。`StrategyRunner.stop()` 会 abort 在途影子调用并等它们收尾,不会在关库后写库。
5. SQLite:`node:sqlite` 同步执行,仓库约定事务内不 await(matrix-study/store.ts 注释),影子判断的 `BEGIN IMMEDIATE`(预算 claim)与下单链路不会交叉。

**预算**:每个运行每 UTC 日一个原子预算,作用域 `live:shadow:<run_id>:<utc_day_ms>`,上限 `JEV_SHADOW_MAX_CALLS = 200` 次、`JEV_SHADOW_MAX_USD = '0.03'`(= 200 × `JUDGE_MAX_CALL_USD` $0.00015)。每次调用按单次上限原子预留(`AtomicCallBudget.reserve`,与挡单同一实现),回执没带用量不释放预留。调用前先看一眼预算,超了就不调,记一条 `shadow_budget_exhausted`(每运行每天一条);并发下预留撞上限同样记成这条。影子调用也计入 Jev 客户端的全局日上限(默认 $2),200 次/运行/天在实测单价($0.00003/次)下约 $0.006。

**模型不可用**:决策连接没绑定 → 静默跳过,记一条 `decision_model_unbound`;连接读坏 / 预算表冲突 → `decision_model_unavailable:<原因>`。同一运行同一天同一原因只记一条(账本 id 按 `run + day + reason` 确定),不刷屏、不推重复 SSE。

**开关**:

- 运行参数 `jev_shadow`(布尔,默认开)。`POST /api/strategy-runs` 与 `PATCH /api/strategy-runs/:id` 都接受;改它**不需要** LIVE 确认(不动钱)。运行视图总带 `jev_shadow: boolean`。
- 进程级总开关:环境变量 `TG_JEV_SHADOW=0` 时 runtime 不装配 `jevShadow` 依赖,所有运行都不做影子判断。
- 前端:Jev 判断流里点开一条影子判断,有「关掉这个运行的影子判断」按钮(发 `PATCH {jev_shadow:false}`)。

## 2. 挡单判断(gate)语义不变

带 judge 块的候选仍走 `judgeWithBars`,输入完全一致(录制源外包一层只做记忆的 `memoMicro`,读一次、原样返回);`judge_runtime_missing` 仍 fail closed;挡单结果、运行事件(`agent_follow` / `agent_skip` / `skip:ir_judge_skip`)都不变。新增的只是:结果算完后再往账本写一行 `mode='gate'`,写失败被吞掉,不影响挡单。

唯一有意改变:runtime 装配里挡单判断的作用域从 `strategy_run:<run>:<day>` 改为 `live:gate:<run>:<day>`,让实盘判断在 `research_judge_decisions` 里以 `live:` 前缀和回测(`matrix:`)、ASP(`asp:`)区分。改前实盘挡单判断一条都没有,不存在旧键续用问题。

## 4. 接口

`packages/gateway/src/demo/routes-judge-live.ts`,在 `http-extra.ts` 注册(一行 import + 一行列表)。

**`GET /api/judge/live?limit=&run_id=`** → `{ items: JudgeLiveItem[], summary: JudgeLiveSummary }`

- `limit` 1–500,默认 50;`run_id` 须形如 `run_[a-z0-9]+`,不合法 400。
- `JudgeLiveItem` = 账本行 + `outcome`:候选之后的真实线程(同运行、同币、同方向、`created_at ∈ [as_of, as_of + 2×周期)` 的第一条)→ `{thread_id, status, opened, closed, realized_r}`;关联不上为 null。

**`GET /api/judge/live/summary?run_id=`** → `JudgeLiveSummary`:

```
{ day_start,
  today: { judged, calls, cost_usd, reserved_usd, follow, skip, follow_ratio, errors, skipped, shadow, gate, skip_reasons: {code: n} },
  budgets: [{ run_id, max_calls, calls, max_usd, spent_usd, reserved_usd }],       // 今天各运行的影子预算
  comparison: { window_from, follow: Bucket, skip: Bucket } }                        // 近 30 天影子行按 Jev 的 follow/skip 分桶
Bucket = { judged, traded, closed, wins, realized_r_sum, avg_r }
```

`calls` / `cost_usd` 取原子预算表里今天 `live:*` 作用域的预留次数和已结算花费(真实发出的请求数),`judged` 是今天账本行数。

**SSE**:每写入一行,运行器 `emit('judge.live', row)`。`http.ts` 的 EVENTS 白名单归别的会话、本次没改,所以路由模块自带一条 `GET /api/judge/live/stream`(`event: judge.live`,15 秒 ping,断开即解绑)。以后白名单加上 `'judge.live'`,`/api/events` 会同样转发同一份数据。

## 6. 剩余风险 / 以后做

- 影子判断发出后进程被杀:`research_judge_responses` 留一行 pending、预算留一笔预留(最多 $0.00015),不会重发;当天该运行的影子美元上限因此略紧。
- 同一收盘多币的状态若完全相同,Jev 请求按 `request_hash` 复用一次回答(与回测一致),账本每币各一行、费用只算一次。
- `/api/judge/live*` 与 `/api/strategy-runs` 一样不在 privateApi 名单里(GET 允许跨源读);内容不含密钥,但包含策略名和候选价位。要收紧需改 `http.ts`。
- 结果对照只对影子行做;关联规则是时间窗 + 同币同向,手动平仓 / 反手产生的线程可能错配到最近的候选。
- `judge.live` 进 `/api/events` 白名单需要改 `http.ts` 一行(归别的会话)。
