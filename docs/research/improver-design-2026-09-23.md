# 策略自动改进与复验环(Improver)设计 · 2026-09-23

## 为什么要这个

研究工作台现在能回答「这条策略历史上怎么样」,回答不了「怎么改才能赚钱」。用户的目的是赚钱,研究只是手段。改策略所需的零件都已经有了:
- 诊断 `loop/diagnose.ts`:指出止损过紧、资金闲置、样本外衰减、利润集中;
- 参数派生 `loop/sweep.ts`;
- 逐段替换归因 `attribution.ts`;
- 修订链 `loop/revisions.ts`;
- 策略对象的版本管理 `strategies/`;
- 零模型全窗口回测 `backtest-report.ts`。

缺的是把它们串成一个有纪律的闭环:诊断出问题 → 生成候选改法 → 只在训练段上挑 → 验证段复验 → 锁死的留出段最后验一次 → 能留下的才进策略版本。自动改策略最大的风险是在历史上过拟合,所以这个环的核心不是「会改」,而是「每改一次都记账,最后敢说这不是噪声」。

## 一、数据与切段

- **冻结**:一次改进任务冻结一个资产池(≥ 4 个流动性最好的币,默认 BTC/ETH/SOL/DOGE/XRP/BNB)× 一个周期(1h 或 4h)× 一段时间(≥ 2 年)。数据 id 写进任务,重跑结果完全一致。
- **三段**:
  - 训练段:前 50%,内部做 4 折滚动前推;
  - 验证段:中间 25%;
  - 留出段:最后 25%,每条谱系只允许用一次,用于最终门槛。
- **成本**:沿用回测口径;另外每个候选都做一次 2 倍手续费的压力测试。

## 二、目标函数(要 Jacky 确认)

目标在跑之前定死,跑的过程中不许改:
- **主目标**:训练段各折扣成本后夏普的中位数,折和折之间的稳定性一起算进去。
- **门槛**(不满足直接淘汰):
  - 每折成交 ≥ 10 笔,全段 ≥ 30 笔;
  - 最大回撤 ≤ 35%;
  - 2 倍手续费下收益仍为正;
  - 相对「同敞口持有」的超额为正,也就是择时本身要有贡献;
  - 回测结果在参数邻域里是一块平台,而不是一个孤立的尖峰。
- **比较对象**:同敞口持有、资产池等权持有、BTC 持有,三个都要报。

## 三、候选生成器(五种改法)

每个候选 = 父 IR + 一个 diff + 生成器名 + 理由。
1. **诊断驱动**(确定性规则):
   - 止损过紧 → 换结构止损或放宽 ATR 倍数;
   - 资金闲置 → 加资产或放宽方向门;
   - 样本外衰减 → 减少条件或参数;
   - 利润集中 → 加分档止盈或保本;
   - 成本拖累 → 换更高周期或改限价入场;
   - 某类离场亏钱 → 换这一段离场原语。
2. **参数邻域**:主要参数 ±25% 和 ±50%(复用 sweep.ts),同时用来做平台检验。
3. **组件替换**:把信号、离场、止损、方向门中的一段换成原语库里同类别的其他原语(复用 attribution.ts 的逐段替换)。
4. **事后反推(oracle)**,即 Jacky 提的「逆过来反推怎么开单才赚」:
   - 在训练段上,给每根 K 线打事后标签:按固定机械管理(下一根开盘进场、2×ATR 止损、吊灯追踪、最长 48 根)能跑到 ≥ +2R 的记为好点。多空分开标。
   - 每根都算只用当时及以前数据的特征:结构位、高周期方向、成交量比、布林带宽分位、时段、形态标记、资金费和持仓量(有数据才算)。
   - 找能把好点和其余点分开的特征组合,规则最多 3 个条件,用浅层规则树。
   - 用打乱标签的置换检验给出 p 值,把「能归因」还是「只是噪声」写明白。
   - 标签本身用了未来数据,这是方法固有的;真正的检验是把挖出来的规则当成入场条件,拿到验证段和留出段上跑真实回测。
5. **模型提议**(可选,有预算):把诊断结果和父 IR 交给模型,让它给出 IR diff 和理由。默认关闭;开启时每轮上限 N 次调用。

## 四、评估流程

每一代的流程如下:
1. 父策略跑诊断;
2. 各生成器产出候选,每代最多 8 个;
3. 零模型编译检查;
4. 训练段 4 折回测;
5. 按门槛淘汰,再按目标排序;
6. 前 2 名进验证段复验;
7. 验证段仍然优于父策略的,才成为下一代父策略。

停止条件:连续两代没有改进,或者预算用完(代数、候选数、墙钟时间、模型调用任一达到上限)。结束时只有冠军去跑留出段,而且只跑一次。

**防过拟合要记的账**:
- 每条谱系累计试了多少个候选;
- 用试验次数折算后的夏普(Deflated Sharpe),以及回测过拟合概率 PBO(用组合对称交叉验证估);
- oracle 规则的置换 p 值;
- 随机入场加同样离场的基线,用来检验入场本身有没有贡献。

报告里这几项和收益一起展示。

## 五、产出与去向

- **改进报告**:谱系树(每个节点是哪个生成器改的、改了什么、各折指标)、排行榜、留出段结果、上面那些防过拟合指标,以及「为什么更好」的归因(哪一折、哪类离场、哪个资产带来的改善)。
- **进策略对象**:冠军以新版本写入 `strategies/`,状态为 backtested,附谱系和留出段报告。往 paper 或 live 推进,仍然要人确认。
- **前向影子**:jacky-24 的 CandidateV0 会自动挑 ≤1h、只做多、不用 Pine 的研究版本,在实时行情上做影子,这才是真正的样本外。改进环的冠军满足这些条件,就会自动进入影子验证。

## 六、工程形态

- 模块 `packages/gateway/src/demo/research/improve/`,入口 `runImprovement(job)`。
- **跑在 worker_threads 里**:用一条单独的 DatabaseSync 连接;Pine 端口通过 workerData 传进去。它不和交易抢主线程,也是交接 P0 的正式解法。
- 表:improve_jobs(任务、冻结数据、目标函数、预算、状态)、improve_candidates(谱系、diff、生成器、各折指标、门槛结果),新迁移。
- 接口:
  - `POST /api/research/improve {strategy_id|strategy_ir, universe, timeframe, budget}` 发起任务;
  - `GET /api/research/improve/:id` 查进度和谱系;
  - `POST /api/research/improve/:id/cancel` 取消;
  - SSE 推送进度。
- 前端:策略详情页加「自动改进」按钮,运行时实时显示每一代,结束后展示谱系树和排行榜,可以「采纳为新版本」。研究对话里的「帮我改进这个策略」也走这条链路。

## 七、分阶段

- **第一阶段**(现在做):
  - 冻结数据与切段、目标函数(参数先按上面的默认值,可配置);
  - 生成器 1–3;
  - 四折评估、门槛、谱系记账、Deflated Sharpe、随机入场基线;
  - worker 线程与 API;
  - 测试。
  
  完成标准:对一条现有策略(比如 20/50 均线)在 6 个币的 1h 上跑完 3 代,产出谱系、排行榜和留出段结果;网关每 2 秒探一次 `/health`,最大响应 < 1 秒;全程零模型调用。
- **第二阶段**:oracle 生成器、置换检验、PBO。完成标准:给出特征组合的 p 值,至少一条规则在验证段扣成本后期望 > 0,或者如实给出「没找到」。
- **第三阶段**:前端谱系与排行榜页面、模型提议生成器、研究对话接入、冠军写入策略版本。
