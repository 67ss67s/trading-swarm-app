# Research 独立测试与对抗复核

日期：2026-09-22。复核对象：`work/research-upgrade` 工作副本。

## 结论

本轮发现并推动修复了三项实质问题：历史归一化图的原始数据恢复可能截断/混入其他快照行；首问创建会话导致发送组件卸载和缓存失效目标错误；已完成回测后的模型回答可通过自然语言改写再次要求授权。最终已跑的检查均通过，未发现仍未处理的同等级问题。

没有启动服务、没有操作浏览器、没有修改 Desktop 原仓库，也没有提交 git。报告不声称完成真实浏览器交互验证。

## 发现、复现与关闭依据

1. **归一化旧图恢复丢失证据（已修复）。** 旧实现用 `spec.rows` 所有行恢复单个字段，其他快照没有该字段的行变成了人为 null；原始底表最多保留 5000 行，但完整 points 可能更多。旧图可能出现人为断点或丢失尾部。现在 `legacyRawPoints` 只读取实际拥有该字段的行，保留显式 null、按时间排序，并校验原始行能覆盖全部已绘制时间点；覆盖不足则保留旧归一化图并明确提示。新增回归覆盖乱序、多快照行、显式缺失、截断底表和 `close_time`。

2. **首问创建会话的组件与缓存竞态（已修复，生命周期静态复核）。** 原 `key={sessionId ?? 'new'}` 在首次创建成功后卸载仍有 pending 的组件；旧发送回调按闭包中的 null sessionId 失效缓存，新组件可能永久停留在空会话，并过早解除发送忙状态。现使用独立 `chatInstance`：显式切换会话创建新实例，首次创建保留原实例；创建请求记录 owner，切走后不抢回会话；发送回调按实际 `args.sid` 更新与失效缓存，并保留已受理 inquiry 防止等待 refetch 时提前解锁。返回原会话时仍由服务端状态恢复。pending 重试继续使用原幂等 key；显式切换会话重置草稿，旧实例回调不能清除新实例的草稿。本项通过类型检查和控制流复核，但未做浏览器异步交互测试。

3. **回测已完成却再次请求授权（已修复，失败转通过回归）。** 原正则可被模型文本 `回测还没有执行，请批准。` 绕过：复现时输出同时含该错误文本、真实 run 引用及结果追问。新增后端第 19 条测试先得到 18 过 / 1 失败。修复后，完成回测的执行叙述和下一步问题由代码按真实结果产生，模型仅能提供经验证的引用；19 条全部通过。零交易场景仍明确没有交易，成功 run 无普通 artifact 时也不再错误显示没有数据。

4. **历史步骤绑定（回归通过）。** 冻结的历史 inquiry、没有 key 列的数据库 step id、原始 `plan` 与消息 `steps` 两种形式均有覆盖。SSR 同时渲染两个相同 step key 的 inquiry，确认旧完成计划显示 `1/1`，当前运行计划显示 `0/1`，不会互相借用状态。

5. **单位、空值与错误含义（回归通过）。** 分数与百分数区分，资金费保留每期单位，null 不转零；tooltip 按真实时间找近邻，保留该时刻的空值。SVG 在显式 null 处分段，孤立有效点仍可见。多资产表使用分析对象的单位显示收益/回撤，样本不足显示空值。预算、参数校验失败、前置失败、超时、取消与数据覆盖缺口分别有回归；后端执行 error 不生成市场缺数据块，不向普通回答暴露 schema dump。

## 验证边界

- 浏览器拖拽、窄屏布局、实际鼠标 tooltip、首问/切换会话的真实网络延迟交互仍需在可启动预览服务的环境验收。
- 当前没有 React DOM 测试环境依赖，因此异步组件生命周期只做控制流复核；SSR 不能证明浏览器交互完全正确。
- 审查范围不包含交易执行权限、资金操作、回测统计方法正确性或外部行情数据质量。
- 父代理计划在此报告完成后微调结果面板来源展示并执行最终 typecheck/build；该最后展示微调不属于上列测试运行时点。
